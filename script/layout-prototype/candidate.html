        Candidate protocol and its safety limits

        State ownership and ordering
        Each approved client and enrolled server stores the replicated operation set and a durable checkpoint. The relay stores opaque encrypted current state separately from its seven-day pending-command inbox. Sessions, processes and runtime freshness belong to their assigned servers. Selection, focus and display preferences remain client-local.
        

        Operations bind account, membership checkpoint, issuer, issuer sequence, causal dependencies, entity identity and typed changes. Verify signatures and account association before ingestion. Fetch missing dependencies before durable acknowledgment. Missing-dependency operations remain in a bounded retry buffer without durable acceptance, and are retried when prerequisites arrive. A per-issuer chain detects gaps and equivocation; a fork freezes the affected stream and conservatively pauses new attachments and destructive cleanup account-wide. Existing processes keep running. Revoking the forking issuer does not resolve its ambiguous history; trusted checkpoint repair is required. The prototype has no repair action; production must implement and validate trusted checkpoint repair. Causally later field values win. Concurrent values use validated logical clock followed by ASCII stable operation ID. Independent fields merge; losing concurrent values are recoverable. Wall-clock timestamps never decide the winner. Schema checks restrict identifiers to bounded ASCII, reject reserved object keys and nested field values, enforce typed field names and cap each encoded operation at 64 KiB. Structurally valid records rejected for epoch or membership remain in a bounded local recovery quarantine; they are never automatically accepted or executed. Unauthenticated or unknown-issuer payloads are dropped. Identical authenticated rejections are deduplicated. Dependency and recovery buffers share a per-issuer cap of 32 records / 64 KiB as well as the global budget. If a buffer is full, refuse acknowledgment so the sender retains its original record. The schema has no forward compatibility: unsupported or malformed records receive no acceptance acknowledgment, and the sending endpoint must retain its original data.
        

        The model serializes these fields as canonical sorted-key JSON for disposable signing checks. Production must define a versioned canonical encoding, size limits, integer/string restrictions and domain separation shared by Swift and Rust. Fresh content keys and signed private records follow the accepted account-trust direction; this page implements no HPKE or encrypted relay storage.
        

        Deletion and concurrent content
        A workspace close enumerates the content identities visible in the closing client's causal view. The atomic transaction records explicit deletion tombstones and close intents for those observed runtimes. Deletion wins over edits and moves of those identities. Recovery of a deleted item uses a new identity; old identity tombstones are never removed merely because a queue expires.
        A concurrent, unseen new terminal has no deletion record. It remains live in a deterministic Recovered work projection, preserving its content identity, assigned server and runtime instance. Invalid parent types, missing ancestors and cycles also enter that projection, without killing processes. A production projection needs deterministic synthetic folder/workspace/pane IDs; this model exposes the affected identities and reason rather than implementing native recovery UI.
        

        Local closure and process confirmation
        An active foreground process or stale/unknown aggregate process report requires confirmation. A fresh report that every affected target is an idle shell closes immediately. Persist both structure changes and outbox before local acknowledgment; storage failure leaves the item visible. Cancel produces no operation. Confirmed items disappear immediately, and cleanup retries in the background. A remote rename preserves local focus; deleting the focused item chooses a surviving local item.
        A healthy process-metadata subscription must bind server, session, runtime instance and sequence. A disconnected subscription is stale immediately. The precise age threshold while connected remains a production measurement. A last-known idle report cannot eliminate the race where a new foreground process starts just after the report; making that impossible would require a server round trip, contrary to the agreed immediate local workflow.
        

        What authorizes runtime termination
        Never infer deletion from absence. Require an authenticated explicit tombstone plus an authorized cleanup request naming the exact account, server, content identity and runtime incarnation. Direct delivery needs a live connection. Rejoining servers synchronize authorized state before enabling attachment, validate complete manifests/dependencies and reject rollback against their durable checkpoint. Incomplete fetches, stale snapshots, removed servers, missing authorization and failed transports preserve processes.
        

        The model injects membership, complete-manifest validation and a nonce-bound authenticated connection as fixture facts. A fresh nonce prevents replaying a previous connection transcript; it does not prove globally latest layout or membership. Withheld relay updates can delay revocation under the accepted trust policy. Direct synchronization uses pinned endpoint identities and the latest verified membership known to peers; it does not require the account ordering server to be online. A server with newer local security state rejects older evidence. If the original delete issuer is now revoked or its epoch is stale, cleanup pauses until a currently authorized peer revalidates and endorses the existing deletion for the exact runtime. That endorsement flow remains to be implemented and tested.
        

        The bounded model requires complete synchronization for reconciliation. Explicit live close commands may later use a smaller proof, but must preserve exact-target authorization and duplicate safety. A server missing deletion evidence keeps the process alive until it obtains the evidence.
        

        Delivery, acknowledgment and restart
        The outbox distinguishes locally persisted, unsubmitted, relay accepted, expired and runtime terminated. Relay acceptance acknowledges durable encrypted queue storage only. A target server persists an execution ledger before reporting a signed termination result; retries for the same operation and runtime return the previous result. Stop the process handle for that runtime, never a reused numeric PID. Acknowledged pending commands can leave the relay inbox. The corresponding tombstones and current-state checkpoint remain.
        On reconnect: authenticate, verify known membership/checkpoints, fetch and verify complete state, ingest valid pending operations, reconcile exact runtime targets, then enable surviving attachments and refresh runtime metadata. The model tracks a separate connected/authenticated channel and unique connection nonce for each server, plus per-runtime results. The shared synchronization fixture describes the completeness, account association, membership epoch and rollback status of one account-layout manifest. An incomplete manifest deliberately pauses destructive reconciliation for every server. Individual connection, authorization and readiness facts remain per server. The model demonstrates ordering and duplicate outcomes. Its restart action copies simulated durable state; atomicity holds by construction in the reducer. It does not prove atomic disk writes, native process termination or power-loss recovery.

        Model budgetAt most 10,000 operations or 8 MiB of operation, dependency-buffer and recovery-quarantine data, whichever ceiling is reached first. Refuse local acknowledgment on overflow; never evict safety evidence silently. These limits are not representative of production. The simple model lists all known operation dependencies and repeatedly copies state, so byte growth is quadratic and the byte ceiling will normally be reached well before 10,000 operations. A production causal frontier requires transitive ancestry checks and measured budgets. Native work must measure storage growth and define quotas or archival before shipping.

        Implementation seams and remaining evidence
        Keep a deterministic Swift/Rust-compatible operation codec and merge engine; transactional local layout/outbox storage; verified encrypted snapshot store; retry scheduler; membership/checkpoint adapter; exact-runtime cleanup ledger; and native presentation adapters. Inventory and attention synchronization consume the same entity IDs and durable state, while server runtime observations use their own monotonic sequence and connection freshness.
        Required before production acceptance: Swift/Rust replay interoperability, real transactional crash injection, encrypted relay queue expiry and state recovery, complete-manifest/hash verification, trust-ledger revocation and endorsement, two-Mac runtime-instance cleanup, client restart preserving sessions, direct-only partitions, compaction with old clients and storage/resource measurements. The separate inventory ticket owns real agent activity and attention evidence.
