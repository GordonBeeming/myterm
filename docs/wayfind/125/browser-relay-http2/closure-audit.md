# Browser prototype closure audit

This audit applies the [browser contract](https://github.com/GordonBeeming/myterm/issues/132) and the full acceptance list in [Validate proxy-only browser routing and native workflow parity](https://github.com/GordonBeeming/myterm/issues/160). It distinguishes fixture evidence from release acceptance.

| Required area | Evidence on the wayfinding branch | Closure condition |
| --- | --- | --- |
| Native client and server matrix | Mac, iPhone Simulator and iPad Simulator reached a [native Linux ARM64 Rust fixture](../browser-private-routing/README.md). Mac Swift and Go fixtures covered other independent cases. | Verify the approved design with native macOS, Linux and Windows server endpoints and the required native clients. |
| Assigned-server routing and no fallback | Private DNS and private non-loopback IPv4 worked through Rust. The [Mac restart fixture](native-navigation.md) exercised recovery and the direct observer. [Exact loopback](transport-comparison.md) still bypassed the proxy on Mac and numeric loopback failed on iOS. | The [resolved loopback decision](https://github.com/GordonBeeming/myterm/issues/207#issuecomment-7100141620) approves opt-in aliases. The [combined alias fixture](../browser-loopback-alias/README.md) validates the configured hostname, blocked tested literal forms, and no client-local connections. Verify these controls in the production path. |
| WebRTC | [Per-view Lockdown](webrtc-lockdown.md) disabled the API in the native fixtures. Ordinary and maximize-compatibility Mac views still emitted local STUN. [Companion's native proxy acceptance tests](companion-lockdown.md) verify API removal and zero local datagrams on the phone and tablet simulators. | The [Lockdown trade-off is accepted](https://github.com/GordonBeeming/myterm/issues/206#issuecomment-7099737405). The [combined alias fixture](../browser-loopback-alias/README.md) tested Lockdown on the mapped route. Verify the application with physical mobile devices, the redesigned Mac client and real site workflows. |
| Origins and HTTPS | [Scoped origin trust](origin-trust.md) passed the exact server, hostname, port and certificate checks on Mac. [Same-origin profiles](profile-isolation.md) used separate stores on all three client types. | Verify production server trust provisioning and destination exceptions across clients. |
| Cookie sharing | [Rust authority](../browser-cookie-authority/README.md) verified scope, conflicts, restart and opt-out. The [native restoration test](../browser-cookie-authority/webkit-restore.md) delivered a generated cookie on the first request on both mobile simulators. | Bind state and policy to the live authenticated Rust channel, verify cross-device sync and opt-out at response delivery. |
| Navigation and existing site workflows | [Native fixtures](native-navigation.md) covered redirect, popup, history, CORS and WebSocket reconnection. The [Lockdown comparison](webrtc-lockdown.md) exposed an IndexedDB, FileReader and Service Worker difference. | Demonstrate the required real site workflows on the chosen browser mode, including sites that rely on non-cookie stores. |
| HTML artifacts | [Existing scoped artifact server](native-artifacts.md) enforced relative resources, script policy, origin registration and revocation through Mac WebKit. | Verify remote approval, stable grant identity across reconnect, and native Rust serving. |
| Native file transfers | [Headless delegate fixtures](native-transfers.md) exercised 8 MiB transfers, cancellation and errors. Explicit native mobile downloads passed and response conversion failed in the iPhone comparison. | Verify visible picker/save/share and response-initiated semantics in the chosen browser integration. |
| Authenticated browser transport | [Rust admission](../browser-private-routing/admission.md) and [live revocation](../browser-private-routing/revocation.md) verified the proxy boundary with synthetic admission values. | Exercise real approval-bound account, server and profile identities, credential lifecycle and end-to-end confidentiality through the production channel. |
| Browser creation, agent-open, and remote grants | [Workflow decision](https://github.com/GordonBeeming/myterm/issues/183) defines the expected behavior. | Verify terminal-only workspace creation, automatic agent hooks, independent clients, grant approval without a local UI, approval after reconnect and source-restricted assigned-server destinations through the approved integration. |
| Human review | Wayfinding fixtures and results are published. | Gordon reviews the real native workflows before the replacement is accepted. |

The approved fallback uses an explicitly configured hostname where literal loopback cannot be routed safely. The combined fixture verifies that fallback alongside Lockdown, while integrated native acceptance and the remaining server matrix still apply.
