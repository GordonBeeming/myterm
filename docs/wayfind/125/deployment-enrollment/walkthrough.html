What the native processes demonstrated

Single-use allocation

Twelve native server identities compete over loopback TCP. One wins. A process exits after synchronizing its allocation but before acknowledging it; restart and retry recover the same admission.

Offline reusable enrollment

A separate native verifier checks cached signed delegation while the authority and prior observer are stopped. An unfamiliar server first presented at expiry requires fresh approval.

Independent credential lifecycle

Native creator removal preserves an account-owned credential; operator authorization uses a trusted pipe. Revoking one credential leaves the other usable. Already recorded servers remain admitted; new instances have fresh keys.

Refusal and recovery

Receivers reject altered signed records, a stale signed directory and a second journal writer. Replay fails closed on corrupted or incomplete journal records. Real-clock admission succeeds before expiry and refuses unfamiliar identities afterward.

One behavior to review

A server accepted only through an offline credential remains recognized locally after expiry. When the verifier learns that credential was revoked, it requires fresh approval unless the authority had already recorded the server's admission. The provisional record alone cannot prove that admission preceded revocation.

Limits of this evidence

The experiment caps growth at 16 credentials and 64 lifetime server identities. Saturation checks require revocation and server removal to remain available. These bounds reserve journal space; they are not proposed product quotas. Removed identities keep their slots, so a leaked credential can exhaust future enrollment in this experiment. Product storage needs abuse controls and safe compaction.

    Same-name replacement checks directory identities only. Running sessions, golden images, actual relay opt-in and native product discovery still require implementation acceptance.
