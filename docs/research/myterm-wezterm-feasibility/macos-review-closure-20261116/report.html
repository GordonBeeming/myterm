Decoded pixels and placement metadata
These are actual restored native checkpoint stripes. The gate compares decoded RGBA hashes, stripe dimensions, positions and Kitty placement/cache state with the uninterrupted native client. An image-count match alone does not pass.


What changed
The scratch Rust core now retains last-print location, saved wrap modes, per-buffer margins, keyboard stacks and image-size requests. Cell runs keep dense checkpoints bounded. Sixel color quantization follows the native client. The client rebuilds native stripes from retained image resources using actual fractional geometry.
The native PTY probe owns a real shell in one Rust process. A fresh SwiftTerm process acknowledges import before the owner resizes the PTY and continues output. The same shell PID and exact query replies are checked. This does not prove simultaneous scheduling during import or network delivery.
Evidence boundary
This is a local macOS prototype, not production architecture or release acceptance. No multi-Mac, Linux, Windows, iPhone or iPad validation is claimed. Linux and Windows remain deferred until a multi-Mac version exists.
Unrepresented terminal extensions, animations, parent/relative Kitty placements, arbitrary image overlaps/crops and production eviction behavior still need explicit validation. Limits fail visibly; the exporter is not an exhaustive validator of every terminal feature. Client view refresh, security transport, control leases, generation changes, slow-reader handling and broad application workloads remain integration work.
Defaults and graphemes come from a separate new native template. The experimental importer uses fixed default options with 40 history lines; it is not a drop-in importer for every configured view. Selected comparisons normalize unused blank allocation and default color variants, retaining styles, meaningful hidden cells and image pixels.
